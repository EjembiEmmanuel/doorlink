STEP 3 — USE EVERYTHING WE HAVE ALREADY ESTABLISHED FOR DOORLINK

Do not only use the newly uploaded files.

Cross-reference the implementation against the existing Doorlink project requirements and information already saved/provided for this project.

The overall Doorlink concept is:

Doorlink connects customers/leads with workers and companies, similar to a marketplace such as Airtasker, with Doorlink taking a commission from transactions.

The application is intended to support the automated door and gate industry and should be structured professionally enough to eventually support real businesses, customers, workers, companies and administrators.

The app should also be capable of supporting future integrations such as:

* Supabase
* Stripe/payments
* subscriptions
* transaction commissions
* customer/worker accounts
* company accounts
* admin functionality
* document/manual storage
* compliance and safety information
* notifications
* marketplace functionality

Do not invent unnecessary functionality just because it sounds useful.

Only add functionality where it is supported by:

1. The existing project,
2. The new files/add-ons,
3. Requirements already established for Doorlink,
4. Or something technically necessary to make an existing requested feature actually work.

STEP 6 — REMOVE OUTDATED OR DUPLICATED FEATURES

If the new files replace an existing feature, update the existing feature rather than creating a second version.

If something is duplicated:

* remove unnecessary duplicate code
* preserve functionality that is still required

If a feature is genuinely no longer required, remove it carefully.

Before removing anything, verify that another feature does not depend on it.

This is extremely important.

Do not rewrite the entire application unnecessarily.

Do not delete working functionality simply to make the implementation easier.

Preserve:

* existing working features
* existing data structures where appropriate
* existing authentication
* existing navigation
* existing integrations
* existing UI functionality
* existing business logic

Only modify what needs to change.

If a major architectural change is genuinely required, explain why before proceeding.

* professional
* premium
* clean
* modern
* realistic
* simple to understand
